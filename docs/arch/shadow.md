# 开关影子与 CRC（M2 规范）

本规范约束 M3 Python MockDevice 与 M4 固件，两者必须逐字节一致。CH446Q 不可回读；影子只表示软件记录，不能证明物理通断。纯格式实现位于 `jumperfree/core/shadow.py`，host 可直接导入，不依赖 board。

## 内存值与线格式

`Shadow` 是冻结、带 slots 的数据类。`closed` 为两个 128 位无符号整数；`tags` 为 256 字节，每字节保存一个 0..15 的**未打包值**。默认影子全零。两芯片均保留完整 16×8 位空间；V0.1 板级只允许 X0..X7，X8..X15 未接线，board 遇到这些点返回 `BAD_ARG`。

`shadow_bytes()` 固定输出 160 字节：

| 字节偏移 | 内容 |
| --- | --- |
| 0..15 | chip 0 的 128 位闭合位图 |
| 16..31 | chip 1 的 128 位闭合位图 |
| 32..159 | 两芯片合并的 256 项四位标签表 |

交叉点位号 `bit = x*8+y`。位图采用小端字节顺序：每个芯片的第 b 字节含位 8b..8b+7，最低位在前。标签索引 `k = chip*128+bit`；打包表第 `k//2` 字节中，偶数 k 放低半字节，奇数 k 放高半字节。断开点的标签由操作助手清为 0；board 校验拒绝断开点残留标签、闭合点标签为 0 或未知标签。

`shadow_crc()` 为 `core.crc32(shadow_bytes(shadow))`，即无符号 zlib CRC32，覆盖完整 160 字节。摘要 CRC 为八位小写十六进制，计划 JSON 的 `expect_crc` 为整数。本 CRC 与未来事务 token 字节流的 CRC 是不同对象。

`bitmap_hex(chip)` 是该芯片 16 个字节按字节顺序输出的 32 个小写十六进制字符，**不是整数的十六进制书写顺序**。`parse_bitmap_hex()` 只接受恰好 32 个小写十六进制字符，返回对应 128 位整数。

## 手算例子

闭合 chip0 的 (X0,Y0)、(X0,Y1)，标签分别为 1、2；闭合 chip1 的 (X1,Y2)，标签为 5。于是：

- `closed = (3, 1024)`，位号分别为 0、1、10。
- chip0 位图：`03000000000000000000000000000000`。
- chip1 位图：`00040000000000000000000000000000`。
- 标签索引为 0、1、138；打包表偏移 0 为 `0x21`，偏移 69 为 `0x05`。
- 整个 160 字节中，仅绝对偏移 0=`03`、17=`04`、32=`21`、101=`05` 非零。
- 固定 `shadow_crc = 0xdab003e1`。

`tests/core/test_shadow.py` 用独立拼接的字节与 CRC 字面量锁定此例，M4 应采用同一向量。

## 操作重放

`apply_ops(shadow, breaks=(), makes=())` 返回新影子，先执行全部 breaks，再执行全部 makes。break 要求原点闭合；make 要求原点断开；操作必须位于正确阶段，否则抛出结构化 `BAD_ARG`。break 清除位与标签，make 写入闭合位与标签。输入影子不变。该助手只处理字节模型；标签归属、V0.1 未接线点、坏点和电气短接检查由 board 负责。
