# 软件路由概览

本实现遵循 **Ideas 2026.10.21** 的阶段边界：它是一个可配置 N 节点的纯软件模拟器，用来验证
网络创建、删除、查询、资源占用、隔离和确定性失败语义。N 是模型参数；真实 Jumperless 的节点
清单与正式节点数仍待确认，代码和文档都不把某个数值声称为官方规格。

“任意两点可按需连通”只表示模型可以为一次请求寻找空闲资源，**不等于**所有可能的多网络组合
都能同时存在。不同 net 不共享节点或 link，避免在模型中形成非预期短接。资源不足时 stage 1
直接返回结构化失败；旧模型不会移动既有 net。交叉点模型则已提供 Stage 2 的部分能力：可选的
有界局部重排。

本阶段不包含 CH446Q 寄存器控制、PCB netlist、硬件 Clos 拓扑、固件或物理电气可行性声明。
完整图只是明确标注的仿真资源模型，不能据此推断真实硬件能力。

## 交叉点多跳模型

`route xbar` 使用显式的芯片 X/Y 线、节点固定接线和芯片间固定链路。建网从字典序最小的节点
开始，反复用确定性的最短路把最近的未连接成员接到已有树；固定边代价为 0，每个需要闭合的
交叉点代价为 1。芯片线在 net 间独占，固定连接成一组的线会一起保留，成功路由还必须通过
`find_shorts` 检查。调用者必须在请求中列出同一 attachment line 或同一固定接线连通分量上的
全部节点；遗漏时原子地返回 `NODES_PERMANENTLY_JOINED`，并在 `missing` 中列出缺少的节点。
路由过程中若将未列出节点的 attachment line 纳入 net，也会以同样方式拒绝创建。

这是贪心 Steiner 近似，不保证最少交叉点或最大总体可路由率。可选重排只搜索至多两个既有
net，并限制连接集合对称差 `C_move` 和探索状态数；它不是全局最优算法，也没有 Clos 保证。
除非拓扑连通性等不变量能够直接证明不可达，`NO_FREE_PATH` 只表示预算内未找到方案。
