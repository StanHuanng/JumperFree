# V5 对标资源规模评估

本评估在一个可执行的软件资源图上测试现有 Steiner 路由与有界局部重排。它用于发现规模放大后
的短接、资源独占、原子性和运行时间问题，不是实际 Jumperless V5 接线的复刻，也不是硬件验证。

## 拓扑与未验证假设

芯片数量、每颗芯片的 16 条 X 线与 8 条 Y 线，以及芯片角色来自随包保存的
`jumperless_v5_reference.json`；该参考本身标记为 `verified:false`。可执行图另外采用三组
`verified:false` 假设：

- `BB01`–`BB60` 连接到 A–H：A–D 每颗 8 行，E–H 每颗 7 行，并使用 X8 及以上线路；较低 X 线保留给中继。
- `SF_I`–`SF_L` 分别连接到 I–L 的 X15。这四个名称只是合成测试端点。
- A–L 组成双通道链：共 22 条固定芯片间边。A 用 Y0/Y1 向外；其余中继芯片以 Y0/Y1 接收，并以 Y2/Y3 向外。

因此图中有 12 颗芯片、288 条独占芯片线、1,536 个可闭合交叉点、64 个外部端点、352 个顶点和
86 条固定边。这些数字描述上述软件图，不能外推为真实硬件的可路由容量。

## 工作负载与安全检查

同一操作流会从空状态开始，分别交给普通 Steiner 和有界重排，彼此不共享结果。固定前缀覆盖：

- 芯片内连接、跨 12 颗芯片连接和多端点连接；
- 一个普通路由资源耗尽、局部重排以 7 moves、1 个探索状态恢复的拥塞案例；
- 删除后复用，以及两个显式请求：零状态预算与 6-move 不足预算下的原子失败。

剩余操作使用给定 seed 产生确定性增删扰动，端点始终从排序后的列表选择。默认是 seed 7、共
60 个操作；重排上限为 64 moves、32 个探索状态和 3 个可移除既有 net。
固定探针自带的预算只会进一步收紧这些调用方上限；每项有效预算取探针值与调用方上限的较小值，
并记录在对应请求结果中。

每次操作后都会检查：没有跨 net 短接；芯片线不被两个 net 同时占用；在固定边加全部 net 的闭合
交叉点组成的全局电气图中，每个 net 的声明成员连通、不同 net 不共享分量且没有混入未声明端点；
每个交叉点属于其声明 net 的分量；声明的芯片线与仅由该 net 交叉点导出的实际电气分量严格一致。
评估还检查输入状态
不被修改、失败请求保持原子、成功请求不改变既有 net 的成员集合，以及 move/state 上限未被突破。

## 运行与解读

```bash
python3 scripts/run_scale_eval.py \
  --seed 7 --trials 60 \
  --out out/scale-eval.json \
  --timings-out out/scale-timing.json \
  --max-seconds 30
```

主 JSON 中包含每个请求的结果、失败原因、moves、states、占用量、峰值占用、最终路由摘要和
工作负载摘要。汇总既保留总 `successes`/`failures`，也分别给出 `create_successes`、
`create_failures`、`delete_successes` 和 `delete_missing`，避免把建网失败与删除不存在 net 混为
同一种成功率。计时单独保存，不会让确定性主报告随运行环境改变。两个现有穷举参照在此
规模上都明确记为 `unavailable_at_scale`；成功率差异只用于描述这组操作，不能解释为全局最优性。
超过运行时间上限会非零退出。

所有生成报告应保存在 git 忽略的 `out/` 目录。Stage 2 与 Stage 2.5 仍为“部分完成”：路由是
有界、局部且依赖合成接线的，不包含 PCB、固件、寄存器或 SPI 控制。
